Nodo Ruta: consultar entregas sin parar, y recuperar el servicio con sus datos

MVP reproducible en contenedores: 2 instancias Django + Gunicorn, proxy NGINX 1.28, panel operativo en /panel, datos externos y respaldo automático verificable con SHA-256. Caso ficticio con datos sintéticos y costo $0.

1 El problema (Nodo Ruta)
  • Único punto de fallo: una sola instancia manual; si se cae, operaciones y clientes pierden consulta de entregas.
  • Datos acoplados: viven dentro de la instancia y se pierden o corrompen con ella.
  • Sin trazabilidad ni RTO medido: recuperación manual a ciegas, sin respaldos verificados ni monitoreo.
2 La propuesta (MVP v3 — Encuentro 3)

Dos instancias Django + Gunicorn (app1, app2) detrás de NGINX 1.28; datos externos en data/pedidos.json (solo lectura para las apps); panel web en /panel para probar balanceo y fallos en vivo; servicios ops y respaldo-automatico con sello SHA-256; y CI en GitHub Actions que ejecuta pruebas unitarias y I01–I05 en cada push.

3 Arquitectura del MVP desplegado (Docker Compose)
Observabilidad: /panel (en vivo) · /health · docker compose ps (healthy) · docker compose logs proxy (http= y upstream=)
Honestidad técnica (puntos únicos de fallo locales): el computador anfitrión, el proxy NGINX y el archivo compartido data/pedidos.json. Dos contenedores en un mismo computador NO prueban tolerancia al fallo físico de ese computador.

5 Mejoras clave (Encuentro 3)
  • Django + Gunicorn (2 workers): supera el servidor básico http.server de laboratorio manteniendo intacto el contrato HTTP.
  • Panel operativo /panel: visualización en tiempo real de entregas, balanceo y fallos 503 sin contenedores extra.
  • Respaldo automático: perfiles ops y respaldo-automatico en compose.yaml.
  • CI en GitHub Actions: tests unitarios + validación NGINX/Compose + I01–I05 automáticas.
6 Seguridad y costo ($0)
  • Cero secretos en imagen o repositorio (.gitignore bloquea .env y llaves).
  • Hardening: usuario sin privilegios (UID 10001), read_only: true, cap_drop: [ALL], no-new-privileges.
  • Exposición mínima: un solo puerto local (127.0.0.1:8080); apps aisladas en red interna.
  • Integridad y control: datos en solo lectura, SHA-256 antes de restaurar, límites 128MB/0.5 CPU y rotación de logs.
